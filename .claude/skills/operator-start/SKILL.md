# Start and continue your Operator Stack

## Select the job, then use the installed skill

There are three separate jobs: installation check, full business interview, and first or returning product work. Follow the user's current request. Do not run an installation audit on every start, or begin an interview during an installation check. Recheck only after an update, a missing resource, a changed host, or an explicit request.

This is an installed skill, not a repository or a saved business document. Open resources relative to the actual location or resource identifier the host provides for this skill. Never guess a computer path. A matching title in search results is not an installed skill.

For installation checks, use only the host's installed-skill tools and their exposed resource files. Do not search ChatGPT Library, Google Drive, GitHub, mail, public websites, old conversations or another computer for installation files. Do not connect more accounts, request repository access, or create substitute SKILL.md files. A historical mention of an Operator Stack folder is not this installation.

If a required skill is not exposed to this chat, stop at that dependency. Name the exact skill and ask the user to enable or explicitly select it. In ChatGPT, use Work mode. The user types @startyour and selects “Start your Operator Stack” under Skills; it must become a selected skill in the message. Other skills can be selected by their display names. A typed name alone need not select it. Codex supports $ skill selection. On Claude, use the enabled plugin or project skill. Do not invent unsupported selection syntax.

For business work, confirm the business/client first. Use only the brief and files provided in this chat or identified by the user in this business project. If missing, ask for the file. Do not search other clients' files to fill gaps. Current research or account work can use appropriate sources when requested; the installation-source boundary is not a ban on tools needed for an actual job.

## Plugin identity

When the request names a Claude plugin namespace, use that plugin for operator-start, every product controller and every supporting resource in this conversation. Report its actual name and version. Never choose an older standalone plugin merely because its name matches the Machine being checked. Never combine files from two plugins to make an inventory pass. If the named plugin is unavailable, stop and ask for that upload to be enabled. If multiple plugins could satisfy an unqualified request, list their names and versions and ask which current download to use. Do not silently guess.

## Installation check

Work through these steps in order. Stop on an unavailable dependency and give the exact next step rather than generating a long table of checks that could not run.

1. **Confirm invocation.** Open this installed SKILL.md and `references/installation-tests.md` using the host's skill mechanism. Report the skill name, actual resource location/identifier and one heading read from the reference. If the host does not expose its resource location, say that and report the actual skill invocation/read evidence; never invent a path. Do not infer invocation from an earlier message claiming the skill was loaded.
2. **Scope the check.** Keep package file checks separate from product practice tasks. The request may name every product inventory for a complete file check while selecting only one Machine for a practice task. Follow those two scopes exactly. Use only the product IDs explicitly requested. Open each matching installed `operator-resources-<id>/RESOURCE-INVENTORY.json`. If no product was specified, ask which one to check. Its `requiredSkills`, `skillFiles` and `files` lists define the expected files. `expandedArchives` is build provenance for source ZIPs already unpacked and intentionally removed; verify its `expandedFiles` and their hashes. The original source ZIP is not required after its output files pass. Do not ask to re-deliver that ZIP or mark it missing. A browser Full Stack setup checks its six main Machines; Research requires a separate app check. The Figma libraries have their own access and duplication checks.
3. **Check availability.** Open each required installed skill's SKILL.md. Resolve its references through that skill's actual resource location. Check access to all files listed in the resource inventory, including supporting guides, worksheets, templates and scripts. Use a file/tool access pass where available; do not dump entire libraries into the conversation. For Copy, check all 14 Canon volumes are accessible and read the library's use instructions. For Offer, retain the workbook/calculators, schemas, templates and validators. If another skill must be selected before its files are exposed, ask the user to select that exact skill and resume the remaining checks. Do not silently skip it or substitute repository contents.
4. **Separate host checks.** In Codex/Claude Code, run the downloaded package's `install.py --verify --host <actual-host> --project <current-business-project>`. Ask for the downloaded folder if its path is unknown. The installer verifies bytes without changing files. In a browser, verify actual installed resource access and the practice task. Hash comparison is an additional check only when the host exposes the installed bytes and code execution; if unavailable, report “hashes not checked in this browser.” Do not require a local installer, Mac filesystem or manifest that is not shipped in this host's download. Builder archive validation is separate evidence, not a browser runtime test.
5. **Use the product.** Run only the explicitly selected Machine’s practice task; do not expand a package file check into practice tasks for every Machine. Run its bounded practice task from `references/installation-tests.md`, invoking the actual product controller through the installed-skill tool and opening its necessary resources. Use the same named plugin; another plugin's earlier invocation or matching file hashes are insufficient. Clearly label practice inputs as fictional. Return the actual practice output and its required reviews. Audit the final output against the practice facts, including any new claims or recommendations. Correct failures and rerun the applicable reviews; do not call a failed output passed just because its files loaded. Reading or describing the first-job contract without running the practice task is incomplete. If the practice reference is missing, identify the outdated or incomplete plugin and stop. This is a small workflow check, not the full business interview or a completed real customer job. If an execution-dependent task cannot run on this host, mark that capability blocked and give the supported next step.
6. **Report narrowly.** Give selected product, host, installed skills/resources checked, practice output, any unavailable check and the next step. “Ready for the interview” requires all applicable resource-access and practice checks to pass, plus the local installer check on app hosts. Browser hash unavailability alone is not a failed resource-access check, but inaccessible required files are. A complete package file check plus one Machine’s practice check can start the business interview, but it does not establish that other Machines passed their practice tasks. Report those other tasks as not yet run. Never call an entire collection ready from one Machine's result. No live publishing, sending, payment, tracking-event submission or account changes are installation tests. Verification does not authorize replacing files. For a missing or changed upload, name the exact archive to re-upload and preserve the buyer's own files.

## Complete foundational interview

Read references/full-interview.md and references/intake-officer-interview.md. Use references/02-OUTPUT-CONTRACT.md and references/03-CONSTRAINT-DIAGNOSIS.md for the final artifacts; references/04-MACHINE-CATALOG.md owns scope. Their union is the required foundation. Ask conversationally, one question or closely related group at a time. Adapt language to the business without dropping relevant fields. Do not set a time limit or shorten the interview to make onboarding look fast.

For every field record: answer, source, confirmation date, and status (confirmed, unknown, needs confirmation, or not applicable with a reason). Existing briefs and focused free-tool results can prefill fields, but the user confirms them. Research inferences are never promoted into confirmed business facts.

Preserve every substantive field from both interview references. Ask follow-ups when an answer changes the offer, buyer, economics, constraints or next job. A missing number stays unknown, not zero. An unresolved required fact remains an explicit gap; do not mark the interview complete just because the user wants to skip it.

When all applicable questions have been addressed, show the factual summary and gap list. Ask the user to approve or correct it. Save BUSINESS-MEMORY.md and a Constraint Card in this business project only, or return them as downloadable files when the host cannot write persistent project files. Be explicit when a new chat will require those files to be attached again. Never promise memory that the host cannot persist.

Use the confirmed brief to populate the adapters of the products this buyer owns (for example the research ground-truth block, EMAIL-OPERATING-CONTEXT.md, account snapshots, economics worksheets); skip adapters for products not installed. Ask only supplemental product-specific questions. Do not create competing copies of the business truth; record adapter derivation and refresh when the approved brief changes.

## First useful job

Ask what the buyer needs to ship or decide now. A settled offer does not need rebuilding before every other Machine can work. Route within the actual owned product and its controller's scope. Preserve every required module, review, source check, output artifact and release gate. This skill is an entry and continuity layer, not a replacement for a product controller.

Google Ads works for online stores and lead businesses; a lead business judges it on qualified leads, booked calls and won deals. Research runs only in Codex or Claude Code, with local files, Python and a web search tool. Static outputs need rendering and review. Funnel architecture requires a writing/build handoff. Layouts require actual website or email-platform implementation. Recommendations are not authorization to change accounts.

Save a short checkpoint in the buyer's project: business, approved brief version, questions answered, unresolved questions, completed artifacts and the exact next action. On return load it and continue. Never rerun completed work without a material reason. Keep interview completion, first reviewed output and real-world use separate. Website milestones are buyer confirmations, not evidence of revenue, deployment or a successful campaign.
